- Perilaku sebelum: no business addon proved the manifest-to-model/view/access/seed path using approval and notification features together; Board had no workflow start/review/history panel.

It adds no request-specific route or duplicate approval-state field. Generic authenticated CRUD and workflow routes handle the lifecycle. Transition definitions may declare `notifyStarter`; transition and outbox event share a transaction.
- Keputusan dan alasan: requester identity uses immutable `create_uid` audit metadata to prevent impersonation; amount is stored as currency minor units; seeded examples remain drafts and do not fabricate workflow history or send notifications at install time. Board visibility is based on available definitions or an existing workflow instance. API checks remain authoritative.
