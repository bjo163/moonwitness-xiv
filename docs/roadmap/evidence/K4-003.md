# Evidence K4-003 — Quran-primary Asma candidate projection

## Named method identity, a collision-free digest, and the first source-derived golden — `dev` `8bd9e6c` — 2026-10-23

The K4-003 verification target is "golden examples, false-positive negatives, reproducibility". The mechanical half of that target is now in the tree. The interpretive half is not, and no code can close it.

`research/profiles/quran-primary-v1.json` `method_policy` requires "a named, versioned analysis method and exact source passage, edition, hash, evidence, and term offsets". The projection did not enforce the first clause: any two non-blank strings given as `method` were accepted, so a candidate labelled `"LLM guess"` / `"v1"` still returned `status: 'candidate'`. `packages/research/src/asma.ts` now requires `mw:asma-method:<slug>` plus a `major.minor.patch` version — the convention `packages/research/src/textual-alignment.ts` already uses for alignment methods — and rejects anything else with `reason: 'method'`.

The candidate digest also omitted fields the record persists. Two candidates differing only in `annotation.context.mode`, annotation or assertion identity, source/edition/locator, or scalar offsets produced the same `mw:asma-candidate:` id, so any store keyed on that id would collapse distinct analytical claims into one row. The identity now hashes every persisted input that can vary while the evidence id stays the same (15 values).

- `ASMA-01` golden over real bytes: `projectAsmaAttributeCandidate`, the production entry point previously reached only through rejection paths, now projects the reviewed Tanzil Q7:46 artifact `corpus/reference/sha256/6f/6ff83b0…7760` after re-verifying its SHA-256 in-test. The candidate `source` block is asserted `toEqual` the profile's authorized passage, including the hash and the rights reference, the scope stays `analysis_not_revelation`, status stays `candidate`, and re-projecting returns the identical record. The digest `mw:asma-candidate:520cc83e540d4325b46e884db03fdb70d6fcf5dddf524f08ab94386b2a4e5acd` is pinned as a reproducibility anchor, so a future change to the identity inputs is reported instead of silently re-labelling stored candidates. The term is the third whitespace token of the line, selected by position: which token in Q7:46 is a divine attribute is a human scholarly judgment and the profile keeps `lexical_inventory: "none"`.
- `ASMA-02` method negatives: eight shapes rejected with `reason: 'method'` — blank id, unnamespaced `synthetic:` id, bare label, empty slug, uppercase-and-space slug, and versions `1`, `v1.0`, blank.
- `ASMA-03` identity negatives: an `analysis` and a `narration` projection of the same span, and a projection under a different annotation id, each must yield a distinct candidate id.
- Non-vacuity: collapsing the digest back to its previous seven inputs fails only `ASMA-03`; restoring the trim-only method check fails only `ASMA-02`. Both mutations were reverted and the files restored from an explicit copy.

Checks: `pnpm --filter @moonwitness/research test` → 15 files, 100 passed (the package type-checks its test sources first); `vitest run tests/asma.test.ts` → 10 passed, up from 7; `@moonwitness/research`, `@moonwitness/api` and `@moonwitness/orm-knowledge` builds pass. Full measurement, environment and the not-measured list are in [the reproducibility report](../../../research/evaluations/K4-003-reproducibility.md). The "Verification" table further down records the 2026-10-16 batch as it then measured (`62 tests across 11 files`, `7 tests` in `tests/asma.test.ts`); those counts are stale and left unedited rather than rewritten, and this section supersedes them.

Still open, and not closable by this package: a named Arabic term-discovery method must be authored by a human (none exists, and nothing here claims to be one), the K3-005 authenticated review rule for persisting a candidate is undecided, no record is written to any store, and nothing was sent to a model or network. No coverage, precision, recall or theological claim is made; no guard, budget or rights scope was widened and no corpus manifest or byte was modified. The task stays `[ ]`.

## Implemented

- Added `research/profiles/quran-primary-v1.json`. The production profile binds the sole locally approved Tanzil source, edition, Q7:46 locator, artifact hash, and rights evidence reference. It keeps interpretation scoped to analysis rather than revelation, records that the lexical inventory is empty, requires named/versioned methods and exact source provenance, and labels historical counts unverified.
- Added `projectAsmaAttributeCandidate`, which accepts a separately analyzed exact term span, accepted source-bound semantic annotation, resolved evidence, and named/versioned method. It emits only a `candidate` with the exact original term, source/edition/locator/hash/evidence/assertion identity, offsets, polarity/context, method, and interpretation boundary.
- Projection fails closed on a source/edition outside the profile, invalid or unreviewed annotation, quoted/reported/negative/uncertain content, counterevidence, invalid offsets, or missing method identity. Candidate IDs are deterministic. No hardcoded name inventory or automatic canonical assertion is produced.
- The public projection API uses only the fixed Quran-primary profile; it has no caller-supplied profile override. The configurable profile core is internal to the source module and is not exported from the package entry point; tests use it with synthetic profiles only. No synthetic phrase is represented as Qur'an content or as a real Asma result.
- Added a profile regression asserting the only authorized passage remains the exact Q7:46 rights-manifest entry, the lexical inventory remains explicitly `none`, historical metrics remain `unverified`, and interpretation scope remains analysis-only. This pins the honest no-result baseline without claiming to run a language analyzer.

## Remaining acceptance

- There is no licensed/source-approved Qur'an corpus beyond the exact Q7:46 Tanzil line in this rebuild. That line is not used here to claim an attribute extraction result. The existing permission covers that exact passage and does not authorize additional verses or derivative corpus records.
- The implementation does not contain an Arabic morphology/lexical analyzer and therefore does not discover candidate terms. As of the 2026-10-23 section above, a source-derived golden over the pinned Q7:46 line, a false-positive negative set, a named/versioned method contract and a reproducibility report exist; the missing piece is a human-authored analyzer method that actually selects an attribute term in Qur'anic Arabic. Positional term selection is a reproducibility fixture, not an extraction result.
- The projection helper accepts a `ResolvedEvidenceReference` as a typed input and cannot prove at runtime that the caller obtained it from the authoritative corpus resolver. A future adapter must call the approved local corpus reader and apply rights/visibility checks; this package helper is not an authorization boundary.
- Accepted annotation fields alone do not establish actor authorization. Trusted review still depends on the K3-005 authenticated workflow adapter, which remains in progress.
