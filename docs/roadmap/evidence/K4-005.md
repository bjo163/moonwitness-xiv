## Implemented

- Added a strict public input contract for a candidate that names two distinct canonical evidence IDs and exact source, expression, edition, locator, content hash, Unicode-scalar range, and quote selectors.
- Resolve each side independently through a caller-provided trusted resolver. The resolver must be bound to the authenticated active tenant and verify canonical evidence, local source rights, edition, locator, and tradition metadata. Resolver-provided tradition context is used; the candidate cannot label its own tradition context.
- Verify canonical passage digest and exact quote/range correspondence before projection. Reject malformed identifiers, extra fields, invalid digests, invalid/out-of-bounds ranges, quote mismatch, malformed Unicode, and identical selectors.
- Snapshot public input and pass detached, frozen selectors to asynchronous resolution so mutation during awaits cannot change the validated identity or citation.
- Project citation-only records with no full passage text. Output is always `TextualParallelCandidate` with `candidate` status and explicit false assertions for identity, quotation, fulfillment, and doctrine.
- Similarity score and method/version are validated caller-supplied metadata. This function does not compute similarity and makes no source-parallel, theological, or historical conclusion.
- Added `TextualAlignmentCandidateVersion` and `storeTextualAlignmentCandidates`/`readTextualAlignmentCandidateVersion` to ORM Knowledge. The store locks and verifies active user, company, and membership in the transaction, re-projects each untrusted input through the supplied trusted passage resolver, hashes canonical citation-only JSON, scopes versions by company, retries identical digests idempotently, and appends changed versions.
- Candidate rows are restricted to `INTERNAL`, denied to the ordinary generic read group, and protected by ORM hooks and SQLite/PostgreSQL append-only triggers. Reads verify tenant access, canonical digest, exact projected object shape, quote range metadata, and interpretation-boundary flags; full passage text and unexpected nested fields are rejected.
- PostgreSQL integration covers concurrent same-digest writes, append-on-change, read scoping, INTERNAL visibility, and append-only deletion. Fixtures use synthetic passages only.
- Tests use synthetic witness passages only. The approved local Tanzil Q7:46 and WEBP Genesis 1:1 samples are not represented as cross-source parallels or used as fixtures in this task.
- No legacy repository is connected or imported, no runtime fetch is introduced, and no screenshot PNG is modified.
