# Evidence K8-002 — private story editorial workbench

## Status

- Status: in progress; a tenant-user/superadmin private story editor, tenant-scoped API, typed client calls, and append-only version workflow are implemented. This slice supports synthetic sample text and one exact local WEBP source artifact whose manifest grants `store`; it does not provide public rendering, publishing, image upload, or general poster composition.
- Date: 2026-10-18 (Asia/Jakarta).
- Dependencies: K5-004 story/page schema and PostgreSQL version store, K8-001 Board shell, and K2-006 owner-approved WEBP Genesis 1:1 source/rights record.
- Data: local tests use synthetic story text. The only media reference accepted by this route is the exact WEBP Genesis 1:1 content-addressed artifact and its verified manifest.

## Implemented

- Added private `GET` exact/latest version and `POST` append-version endpoints. Both require an authenticated tenant user or superadmin and active company context; storage enforces current active company membership inside PostgreSQL transactions. Responses are `private, no-store`, and foreign or unavailable records return the same generic response.
- Reuse the strict versioned Story/Page store for canonical digests, previous-version chain, exact text preservation, idempotency, and append-only storage. The request schema rejects additional properties, including public publication fields.
- Added a local-only media resolver. It re-reads the pinned textual-witness artifact and manifest, verifies the artifact ID and source manifest, and requires `store` permission. The route accepts only that exact approved artifact reference; it does not fetch external URLs or accept uploaded bytes.
- Added SDK types and typed methods for reading and storing story versions.
- Added a lazy Story Workbench Board route, visible to tenant users and superadmins with a selected company. It lets editors select, add, reorder, remove, and edit pages in an explicitly synthetic INTERNAL sample, then appends the complete page list as one immutable revision. Reordering retains page IDs; removing a page only affects the new snapshot and never deletes prior revisions. Existing verified media references stay attached to their pages. Publishing and media uploads are unavailable.
- Added a private portrait 3:4 page-composition preview that follows the selected page and unsaved draft, including while inspecting a prior revision. It has spacing for the sticky Board toolbar, is labeled internal-only, and provides no export or publication action.
- Distinguish an unavailable read from an explicitly missing sample: transient/API/authorization errors show generic retry guidance, preserve the editor draft, and disable save until the current state is confirmed. An explicit not-found response can still start the first revision. A mocked 503 → retry → 404 browser regression asserts draft retention and no automatic POST.
- Extended the corpus passage snapshot with its source artifact identity and tested that requesting storage requires the manifest's `store` grant.
