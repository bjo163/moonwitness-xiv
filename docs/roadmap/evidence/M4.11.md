## Contract

- Generic REST/JSON-RPC mutations write the business row, audit record, and outbox event in the same transaction. A failed outbox insert rolls the business mutation back.
- Outbox delivery claims are leased and fenced. Delivery increments attempts while preserving the stable outbox event ID across retries.
- A successful external receiver effect followed by local acknowledgement failure can be delivered again. Receiver-side deduplication using the stable event ID prevents duplicate effects when the receiver implements that contract.
- Semantics are at-least-once; the outbox does not claim exactly-once external effects.

## Limits

- The fake receiver proves stable ID/deduplication behavior locally; no real external provider was contacted.
- A receiver must durably store/deduplicate the event ID for its own effect. If it does not, duplicate external effects remain possible after acknowledgement loss.
- Hosted CI status is recorded after push; no CODEOWNER promotion or merge is implied.

## Recover a persisted outbox lease after worker restart — `129f838` — 2026-10-15

- Added package and PostgreSQL tests for the crash window after the receiver has applied its effect but before the outbox event is acknowledged. Each test starts from a persisted `processing` row with an expired lease, attempt 1 and fencing token 1, then dispatches it as a restarted worker.
- Both tests prove redelivery uses the same event ID, a receiver deduplicating that ID applies its effect once, PostgreSQL/SQLite advance attempts and fencing token to 2, the event reaches `published` with its lease cleared, and a subsequent dispatch does not redeliver it.
