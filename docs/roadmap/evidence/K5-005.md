# Evidence K5-005 — character canon and terminology reconciliation

## Status

- Status: in progress; a synthetic-only persona contract, type validator, and negative tests are implemented. No canonical persona records or real alias mappings have been added.
- Date: 2026-10-17 (Asia/Jakarta).
- Dependencies: K5-003 synthetic witness/research domain and K3-003 identity reconciliation contract.
- Storage: canonical persona and review records remain PostgreSQL-backed. This slice adds no persistence adapter or registry file.
- Source limits: aliases and roles must reference entries listed in `source_refs`; this checks internal attribution only and does not resolve or verify a source. Test fixtures are synthetic.

## Implemented

- Added `ontology/mappings/narrative-persona.schema.json` with strict `mw:persona:*` identifiers, typed aliases and roles, source-reference fields, and optional reviewed identity association.
- Added `validateNarrativePersona` to `@moonwitness/research`. It requires alias/role references to occur in the record's `source_refs`; aliases do not imply equivalence and extra canonicalization properties are rejected.
- Historical identity association is limited to `mw:entity:*` or `mw:agent:*` and requires the exact persona/identity pair in a structurally valid, accepted K3-003 candidate and decision. The validator treats supplied decisions as structural evidence only; production must resolve canonical decisions from trusted, company-scoped storage and verify review history before any persistence or identity operation.
- Extended the identity decision schema to allow a persona identifier as a candidate participant while preserving the separate `mw:persona:*` namespace.
- Added synthetic tests for source attribution, namespace separation, unexpected `same_as`/canonicalization fields, missing and rejected decisions, conflicting decision input, unrelated/self associations, and work/concept IDs.
