# M1.08 — Risk-based promotion policy

## Policy

The `dev` to `main` promotion remains an automated pull request. CI classifies the full
commit range and changed-file diff, independent of labels. Compatible changes in ordinary
application code may use GitHub auto-merge after all required checks pass. A breaking
change, security-sensitive commit or scope, sensitive path, deletion, or invalid commit
message requires explicit review and a manual merge.

The classifier treats workflow and repository policy files, authentication and production
configuration, all API source, ORM/add-on/job packages, model and manifest definitions,
dependency and container manifests, and operational scripts as sensitive. CODEOWNERS
assigns the repository maintainer to those areas. For renames it
checks both the old and new paths. An `approval-required` label records the decision for
maintainers; the label itself is never an input to the classifier.

For a sensitive promotion, the required `ci-gate` fetches pull request reviews and accepts
an approval only when its commit SHA exactly matches the current PR head and the reviewer
is listed as a user in `.github/CODEOWNERS`. A later review from that owner on the same SHA
replaces their earlier decision, so a change request or dismissal cannot leave an old
approval effective. A new commit changes the required SHA and makes earlier approvals
stale. The promotion workflow disables existing auto-merge for sensitive work and leaves
the PR for a manual merge after CI passes.

Both CI and promotion can be started manually from `dev` for recovery after a sync push
made with `GITHUB_TOKEN` suppresses push-triggered workflows. Manual CI always runs every
required lane and uses `main` as its baseline for commit and risk classification. Manual
promotion rejects any ref other than `dev` and re-evaluates the current branch head.

## Operational constraint

This repository currently has one CODEOWNER (`bjo163`). Sensitive PRs therefore need that
maintainer to submit a GitHub approval on the exact current head SHA; a previous approval,
commit authorship, or a label cannot satisfy the gate. GitHub branch protection still
requires the `ci-gate`; compatible low-risk PRs can auto-merge after that required check.
