## Result

- Dataset releases bind ontology/corpus versions, immutable snapshot digest/path, previous release, and the exact local ingestion recipe path plus SHA-256. The recipe pins its source path and source-byte digest.
- `replayDatasetRelease` verifies the immutable release manifest, previews the pinned recipe, and rebuilds a missing snapshot only when the reconstructed digest exactly matches the release. It then revalidates the snapshot and atomically switches the active pointer.
- A changed/missing recipe or source fails before publication; a mismatch does not change the active pointer. A corrupt existing snapshot is rejected rather than overwritten. Replaying a known-good older release restores a missing snapshot and performs rollback without deleting release history.
- Source files are not duplicated automatically into the raw-artifact store. The recipe-pinned source file must remain available in the local repository/workspace; if it is missing or changed, replay fails closed. Rights clearance remains a separate gate and private-source retention remains governed by K5-001/K5-002.
