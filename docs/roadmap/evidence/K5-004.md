## Episode contract - 2026-10-25

The 2026-10-23 issue audit recorded that this card's title names an `episode` axis that did not exist anywhere in the repository (`docs/roadmap/evidence/issue-audit-2026-10-23.md:53`, "tidak ada model `episode` padahal judul kartu menyebutnya"). This slice closes exactly that axis; story, page, and media were already present and tested.

- Added `ontology/domains/story-episode.schema.json`. An episode is a contiguous page range of one exact story version: it names `story_id`, `story_version`, and `story_digest` together with `first_page_order` and `last_page_order`, and carries its own `episode_id`, positive `version`, `title`, and `visibility` fixed to `INTERNAL`. `additionalProperties: false`, with no status, publication, or render field, so an episode document cannot widen into a publishing instruction. JSON Schema cannot read the referenced story version or compare the two orders; the storage layer must.
- `validateStoryEpisode` adds the range check (`first_page_order` must not exceed `last_page_order`) on top of the schema.
- Added the `knowledge.story_episode_version` model and `knowledge_story_episode_versions` table. Rows hold the canonical episode document, its SHA-256 digest, the bound story identity and digest, the range, the derived page count, tenant, recorder, and the previous episode digest. No page text is copied into an episode row.
- Story episodes are append-only in both engines: the PostgreSQL trigger function gained its own `RAISE EXCEPTION 'Knowledge story episodes are append-only'` branch, the SQLite path gained the matching `RAISE(ABORT, ...)` branch, and the model joins the ORM `beforeUpdate`/`beforeDelete` refusal list. Manifest version moved `1.9.0` to `1.10.0` so generated documentation fingerprints change with it.
- Added `storeStoryEpisode` and `readStoryEpisode` in `packages/orm-knowledge/src/story-episode-store.ts`. Every write and every read re-derives the returned slice through the story-version integrity reader, so an episode can only return page text the bound story version still proves: digests, canonical form, per-page row match, the previous-version chain, and media re-resolution are all re-checked first. A range that no longer matches the stored page order throws inside the slice helper and surfaces as a refusal or a `null` read, never as a reordered slice.
- Fail-closed refusals, each verified to leave zero rows: a story version that is not stored in this company, a `story_digest` that differs from the stored version, a range outside that version's page count, a `first_page_order` above `last_page_order`, a skipped episode version, a same-version replay with different canonical content, and any cross-tenant read. Because the same reader is reused, withdrawing or failing to resolve a media reference inside the bound story version makes the episode read return `null` too.
- Concurrency and idempotency follow the story writer: tenant-wide `SELECT ... FOR UPDATE` serialization, append-the-next-version only, and exact canonical replay returning the stored episode with `idempotent: true`.
- Deliberate reuse instead of duplication: `readVersionRow`, `assertActiveCompanyEditor`, and `isAuthenticatedEditor` became module-internal exports consumed by the episode store rather than a second copy of the story verification logic. They are not re-exported from `packages/orm-knowledge/src/index.ts`, so the public surface gains only `validateStoryEpisode`, `storeStoryEpisode`, `readStoryEpisode`, and four episode types.
- No route, menu, or generic access was added. `knowledge.story_episode_version` is listed in `NON_GENERIC_MODELS` (`apps/api/src/auth/policy.ts:16`) and the existing `apps/api/tests/record-rules.test.ts` matrix denies it for every role and operation even under a full grant. There is no episode renderer and no auto-publish behaviour, matching the card acceptance line.
- File-scope note: the card names `packages/orm-knowledge*/` and `ontology/domains/`. This slice also touches one line in `apps/api/src/auth/policy.ts` and one line in `apps/api/tests/record-rules.test.ts`, which is where the story and page models are already denied. Nothing else outside the named scope changed.
- Tests: `packages/orm-knowledge/tests/story-episode-store.test.ts` (2 tests) stores a three-page synthetic story whose middle page carries the already-approved local WEBP Genesis 1:1 reference, then proves single-page and multi-page slices return byte-exact text (CRLF and trailing spaces preserved), idempotent replay, a second episode version chained to the first digest, `null` when media resolution is withdrawn, and append-only update/delete refusal. The second test walks each refusal above plus tenant confinement and a malformed read context.
- The PostgreSQL lane (`packages/orm-knowledge/tests/postgres.integration.test.ts`) now also stores an episode over the real two-page story version, reads it back, asserts one episode row, and asserts the append-only delete refusal. It was **not executed**: this session has no local PostgreSQL engine (no running Docker daemon, and `C:\Program Files\Docker` contains only `cli-plugins`), and the file self-skips without `POSTGRES_TEST_URL`. These assertions, together with the four already-skipped PostgreSQL files, are the owed gate.

## Implemented

- Added strict `ontology/domains/story-version.schema.json`: stable story/page identifiers, positive version, `INTERNAL` visibility, exact `original_text`, ordered page metadata, and at most one optional immutable media reference per page. The contract has no publication/status field and rejects extra properties.
- Added PostgreSQL-backed `knowledge_story_versions` and `knowledge_story_page_versions` tables in `@moonwitness/orm-knowledge`. Each version stores a canonical manifest and SHA-256 digest, exact page text, per-page text digests, stable page order, optional media reference, tenant, recorder, and previous-version digest.
- Added a transactional writer and integrity-checking reader. It serializes tenant version allocation, requires the next version, permits exact idempotent replay, rejects conflicting or skipped versions, verifies every page row against the manifest, and preserves earlier versions. Writes resolve media after locking the authenticated active-company context; reads re-resolve media bytes and rights and fail closed when the reference is missing, revoked, or unverifiable.
- Story and page rows are append-only through ORM hooks and SQLite/PostgreSQL triggers. Generic REST and JSON-RPC access is denied for all roles; no story publication or auto-publish route exists.
- Media-bearing writes require a trusted local resolver to verify the exact artifact bytes and digest, permitted rights, `store` use, MIME type, and rights evidence reference. Media bytes remain in the existing local content-addressed artifact store; the PostgreSQL rows hold only the reference.
- Added a two-page versioning regression: page ordering is stable, CRLF/trailing spaces and Arabic text are preserved exactly, a verified local source file can be referenced once on one page, a later version can omit it, exact retries are idempotent, and earlier content remains readable and unchanged.
- Added a route-level synthetic canary test proving INTERNAL story/page text is denied through generic REST and JSON-RPC even to an authenticated superadmin.

## Remaining acceptance and limits

- Rerun the complete affected package/API suites and roadmap validation on the candidate SHA, then collect exact-SHA hosted CI and CODEOWNER review before promotion.
- This contract does not create or publish an image, does not transform or copy source text into a story, and does not enable public rendering. The media test references an approved local text artifact; image rendering remains optional and unimplemented.
- Nothing consumes an episode yet. No reader, route, board surface, or export turns an `INTERNAL` story or episode into presentation output, and the card's optional per-page image/file render is still unimplemented; adding one is a separate editorial and privacy decision, not a storage change.
- An episode inherits every story limitation: it is only as current as the bound story version, and because it re-derives its slice from that version, a story page that no longer verifies removes the episode slice rather than showing stale text. Episode rows are never rewritten, so correcting story text means appending a story version and, if needed, a new episode version pointing at it.
- Privacy retention/revocation and broader downstream derivative invalidation remain open under K5-002. Keep real testimony/private story content disabled until owner privacy/safeguarding approval and any required legal review are recorded. The episode table is a further place K5-002 must account for when concealment or erasure is implemented.
