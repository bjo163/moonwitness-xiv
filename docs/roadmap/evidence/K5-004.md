# Evidence K5-004 — story, episode, page, and media manifest contracts

## Status

- Status: in progress; strict versioned Story/Page contract and append-only PostgreSQL-backed storage are implemented for synthetic content. Hosted checks and exact-SHA CODEOWNER review remain delivery gates.
- Date: 2026-10-17 (Asia/Jakarta).
- Dependencies: K5-003 synthetic witness domain and K2-003 dataset release/rollback contract are present. This slice uses the same immutable, content-digested versioning pattern while keeping story records canonical in PostgreSQL.
- Data: test narrative is synthetic. The only media reference test uses the already-approved local WEBP Genesis 1:1 source artifact and verifies its manifest, bytes, digest, MIME type, and `store` rights. No new media bytes or story content were imported.

## Implemented

- Added strict `ontology/domains/story-version.schema.json`: stable story/page identifiers, positive version, `INTERNAL` visibility, exact `original_text`, ordered page metadata, and at most one optional immutable media reference per page. The contract has no publication/status field and rejects extra properties.
- Added PostgreSQL-backed `knowledge_story_versions` and `knowledge_story_page_versions` tables in `@moonwitness/orm-knowledge`. Each version stores a canonical manifest and SHA-256 digest, exact page text, per-page text digests, stable page order, optional media reference, tenant, recorder, and previous-version digest.
- Added a transactional writer and integrity-checking reader. It serializes tenant version allocation, requires the next version, permits exact idempotent replay, rejects conflicting or skipped versions, verifies every page row against the manifest, and preserves earlier versions. Writes resolve media after locking the authenticated active-company context; reads re-resolve media bytes and rights and fail closed when the reference is missing, revoked, or unverifiable.
- Story and page rows are append-only through ORM hooks and SQLite/PostgreSQL triggers. Generic REST and JSON-RPC access is denied for all roles; no story publication or auto-publish route exists.
- Media-bearing writes require a trusted local resolver to verify the exact artifact bytes and digest, permitted rights, `store` use, MIME type, and rights evidence reference. Media bytes remain in the existing local content-addressed artifact store; the PostgreSQL rows hold only the reference.
- Added a two-page versioning regression: page ordering is stable, CRLF/trailing spaces and Arabic text are preserved exactly, a verified local source file can be referenced once on one page, a later version can omit it, exact retries are idempotent, and earlier content remains readable and unchanged.
- Added a route-level synthetic canary test proving INTERNAL story/page text is denied through generic REST and JSON-RPC even to an authenticated superadmin.
