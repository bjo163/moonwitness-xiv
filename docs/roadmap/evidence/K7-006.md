# Evidence K7-006 — Local AI evaluation and model-outage certification

## Model-outage certification at the API boundary — base `dev` `2fd9efa` — 2026-10-24

- What was already pinned before this unit, and what was not: reason mapping lives in `packages/local-ai/tests/runtime.test.ts` (`fails closed on invalid provider response or HTTP errors`, `maps a provider timeout into an unavailable result`) and the adapter's outage shapes live in `packages/local-ai/tests/suggestion-matrix.test.ts` (`provider-failure`, `runtime-timeout`). Nothing drove an outage through the restricted API route, so the "model-outage certification" half of this card had no observable contract at the boundary callers actually see.
- Three tests in `apps/api/tests/local-ai-suggestion.routes.test.ts` (that file is now 18 tests) install the real `createLocalAiRuntime`, built from `readLocalAiConfig({ AI_MODE: 'local', LOCAL_AI_ENDPOINT: 'http://127.0.0.1:41234' })`, behind the route decoration and drive four modes end to end: `disabled`, `timeout` (transport rejects with `name === 'TimeoutError'`), `provider_unreachable` (HTTP 503 from the provider) and `invalid_response` (HTTP 200 whose JSON body has no `text`). The route reads `fastify.localAi.generate` per request, so the swap happens after the shared harness setup instead of duplicating it.
- Certified contract for every mode: `503` with exactly `{ success: false, error: 'Local suggestion generation is unavailable' }`; `Cache-Control: private, no-store`; `knowledge_research_suggestion_versions` stays empty; the reason string, the provider's own body text (`DOWN-FOR-MAINTENANCE`) and the loopback host and port never appear in the response body; the transport is reached exactly once per request for the `local` modes and never for `disabled`.
- The egress piece that is certifiable without a model: every recorded request went to `http://127.0.0.1:41234/v1/generate` with `method: 'POST'`, `redirect: 'error'` and an `AbortSignal` timeout, and both `readLocalAiConfig` and `createLocalAiRuntime` refuse `http://model.example.com` before any transport exists. OS-level egress denial is not claimed here — it still needs the firewall state on the named machine, which the card already lists as unmeasured.
- An outage is not a bypass: with the model down, ten requests return `503` and the eleventh returns `429`, while the provider was contacted exactly ten times, so the failure neither resets nor skips the route's `max: 10 / 1 minute` limiter.
- Four targeted mutations of the route, each restored byte-identical afterwards, show the tests are not vacuous: dropping `unavailable` from the 503 branch fails all three new tests; removing the generation route's `no-store` header fails the outage test together with the pre-existing success-path test; deleting the route's `rateLimit` config fails the pre-existing limiter test and the outage limiter test; echoing `result.reason` into the error message fails the leakage assertions.
- Scope note: this card declares `research/evaluations/` and `docs/operations/` as file scope, and the unit landed in `apps/api/tests` because that is where the boundary contract is observable; it is the "local model-off resilience report" deliverable expressed as tests rather than as a document.
- Suite and gates: both local-AI suggestion files in `apps/api` pass (18 and 4 tests), `eslint --max-warnings=0` and Prettier are clean. `apps/api/tsconfig.json` excludes `tests`, so `tsc` does not type-check this file; the behaviour was verified by the four mutations above rather than claimed from a type-check that does not cover it.
- Unchanged remaining acceptance, all model-dependent: a named local model with an immutable artifact digest, same-source variant comparison, sample-counted p50/p95 latency, trustworthy peak memory, citation/source/span acceptance, unsupported claims, source coverage, and OS-level egress denial.
