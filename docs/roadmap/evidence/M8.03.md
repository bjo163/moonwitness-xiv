## The alert survived the tightened guard and moved to a new line, so the replacement itself was removed — `dev` `d69f661` — 2026-10-24

The accumulated output is then re-checked against the three marker spellings (`<!--`, `-->`, `--!>`) and any survivor aborts the build, so the refusal does not depend on the scanner having predicted every reassembly.

The property the tests pin is the same one — no HTML comment marker reaches a generated component — and it is now enforced by refusing input the generator cannot prove clean, instead of by rewriting it. Well-formed comments, `<title>` elements and adjacent comments (`<!--a--><!--b-->`) keep being stripped, each pinned by an assertion on the exact parsed children.
- Three mutations, each killed by the suite, so neither guard is decorative: disabling the output re-check fails 1 test (a reassembled `<!--b-->` then reaches the parser as text); making the comment needle never match fails 1 test; making the `<title>` pattern never match fails 2 tests.
