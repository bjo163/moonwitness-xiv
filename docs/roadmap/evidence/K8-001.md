## Implemented

- Added a lazy `/knowledge` route inside the existing authenticated Board shell and a role-aware navigation link for `system`/`superadmin`. The page repeats the role check, and server/API authorization remains authoritative.
- Added source selector and exact passage reader for the two already-pinned local samples. The view shows edition, locator, attribution, source identity, and verified content SHA-256; it makes no network request to original publishers and exposes no write controls.
- Added typed SDK support for `GET /api/research/relations/{relationId}/explanation`, displaying the active release digest, relation scope/review status, support/counterevidence, and interpretation boundary. Alternative relations can be opened from the explanation; evidence linked to a supported pinned source can open that source's pinned passage.
- Kept the explorer hidden from ordinary users and added a direct-navigation denial message. The API continues to enforce its own authenticated role and record-visibility policy.
- Extended bounded active-release search to include relations only when the relation and both endpoint nodes resolve to readable `INTERNAL` records. Search summaries expose only relation identity, predicate, visible endpoint IDs, and review status; the existing explanation endpoint remains the source for evidence and alternatives.
- Added Board navigation from a relation search result directly to its existing explanation panel, and expanded the loopback/test-database-guarded live fixture with synthetic endpoints and a synthetic relation. Repeated seeding verifies those records before returning `already-present`.
- Added a polite accessible status region that announces the number of readable graph results, truncation, or an empty search state. The keyboard-driven Board browser test searches a relation, verifies the announced count, and opens its explanation from the result action.
