# M1.11 — Remove application deployment workflows

## Status

Complete on protected `main`. The staging/production deployment workflow and its obsolete
README instructions have been removed from the development source and merged. The former
workflow contained deploy-hook calls for staging and production. Release publication to
GHCR and GitHub Releases remains separate and is not an application deploy.

Container validation is implemented by `scripts/smoke-containers.sh`: it builds API and
Board production Docker targets, starts them with a disposable PostgreSQL service using an
isolated Compose project, checks API root/readiness and Board root, then stops the API and
verifies graceful shutdown. The script uses local-only test credentials and removes its
temporary database volume on exit. It never reads deployment hook URLs or accesses an
external deployment service. README now documents application deployment as
operator-managed outside repository automation, without requiring staging.
