# Evidence M10.05 — API and Board container smoke acceptance

## Production Compose validation broke when the WhatsApp service made its credentials required — observed at `dev` `1460036` — 2026-10-23

- `fddb343` added a `whatsapp` service and made `${WHATSAPP_INTERNAL_TOKEN:?…}` and `${WHATSAPP_SESSION_KEY:?…}` required interpolations in `docker-compose.production.yml` (also in the API, jobs-scheduler, jobs-worker and outbox-worker environments, and in `docker-compose.yml`). Compose interpolates the whole file before it acts on any service, so every invocation fails on a missing variable even when the requested service is `postgres`, `api` or `board`.
- Three callers had no such variables: the CI `containers` job step `Validate production Compose configuration`, the same step in the release `verify` job, and `composeEnvironment` in `scripts/smoke-containers.mjs`. Reproduced locally with exactly the CI environment: `docker compose -f docker-compose.production.yml config --quiet` emitted six "required variable … is missing a value" errors and failed. Hosted confirmation is run [40002616667](https://github.com/bjo163/moonwitness-xi/actions/runs/40002616667), where the `containers` job (`120583270719`) failed on that step and consequently on the scan gate.
- Repair: the two workflow steps now also pass CI-only non-secret placeholders, following the existing `JWT_SECRET: ci-only-secret-…` precedent, and `scripts/smoke-containers.mjs` pins the same placeholders explicitly so a real session key can never be inherited into the smoke stack. With those values the same command exits 0. The production requirement itself was not weakened: no variable became optional, no default was added to either Compose file, and no budget, threshold or guard was lowered.
- Regression guard: `scripts/ci-concurrency.test.mjs` now derives the required variable names from the Compose file itself and asserts that all three callers define them, so the next service that adds a required variable cannot land without updating the lanes that run Compose. Mutation-checked: adding `${PROBE_KEY:?probe}` to the production file failed the new assertion naming the CI caller, and the file was restored from an explicit copy. `node --test scripts/ci-concurrency.test.mjs` passes 9/9 and `node --test scripts/smoke-containers.test.mjs` passes 10/10.
- Not accepted here, and recorded as open risk rather than verified behavior: the `whatsapp-runtime` image in `Dockerfile` is never built, scanned or smoke-tested by any lane; `apps/whatsapp` has no tests and is not selected by any CI job; `/internal/whatsapp/*` is exempt from JWT and gated only by the shared internal token; and `whatsapp_accounts.auth_state` is read through raw `app.db()` calls that bypass the ORM field-level flags. Those belong to the integration's owner, not to this repair. This section proves only that the container configuration lane is repairable and guarded; hosted acceptance on a fresh exact SHA is still required, and M10.05 stays in progress.
