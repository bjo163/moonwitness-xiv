## Delivered

- Added `.github/workflows/pages.yml`. Branch pushes are restricted to `dev` and `main`; relevant path detection skips unrelated changes. Manual immutable source-ref builds are supported.
- Release-tag publication must be dispatched from trusted `main`, reference a published GitHub Release, and point to a commit reachable from `main`; the unpublished `1.0.0-rc.1` baseline tag cannot become a public docs release.
- The build records resolved checkout SHA in `build-info.json`, runs the docs portal build and tests, applies public-output scanning, and only then uploads an artifact.
- Trusted `main` publication waits for the newest `CI` workflow push run on `main` to complete successfully for the exact immutable source SHA, then verifies its `ci-gate` job; a missing, failed, cancelled, or stale check times out/fails closed before artifact upload.
- `dev` uploads a seven-day preview artifact only. `main` and explicitly selected release tags upload a Pages artifact; deploy job alone receives `pages: write` and `id-token: write`.
- Manual publication validates `source_ref`: main dispatch checks out `refs/heads/main`; release tags must be published and reachable from main. An arbitrary `dev` ref cannot opt into deploy.
- A stable concurrency group prevents overlapping deployments from racing; artifact-based Pages does not create `gh-pages` or any branch.
