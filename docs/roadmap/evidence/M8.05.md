## Planner report grounded in local evidence and batch-bounded — `dev` `fdfa432` — 2026-10-23

- Issue #54 asked that each candidate report state what it touches before anyone applies it, and that "review the whole plan" not remain the de-facto batch size. `scripts/dependency-update-plan.mjs` now derives three fields per candidate from files already in this checkout, so planning needs no registry token and no network call beyond `pnpm outdated`:
  - `releaseNotesSource` (`registry-manifest` → `action-reference` → `installed-manifest` → `unavailable`) plus the resolved URL, so a citation is never presented as more authoritative than it is. `pnpm outdated --recursive --format json` carries no repository metadata, so the primary offline pointer is the manifest already resolved in `node_modules/.pnpm`; npm `repository` shorthand strings (`owner/repo`) are normalised to an HTTPS GitHub URL.
  - `localUsage`: a `git grep` scan of `apps/`, `packages/` and `scripts/` returning the referencing files and the exact import specifiers. The first probe used `(?:` , which POSIX ERE rejects and silently returned nothing, and an earlier version used `git grep -h` whose output has no path segment, so `referencingFiles` was always 0; both are fixed with `-n` plus a capture group.
  - `impactedWorkspaces` and `testImpacts`: the dependent package locations are mapped to workspace paths and each path selects CI lanes (`apps/api` → integration + e2e, `apps/board` → e2e, `apps/docs` → docs:check + docs-portal, `apps/ui-catalog` and `packages/ui` → ui-catalog/ui-budget, `packages/assets` → assets, `.github` → action-pins, workflow-trust, ci-gate, action-tags), with `pnpm typecheck` + `pnpm test:unit:built` as the fallback floor and the order fixed by `GATE_ORDER`.
- `selectBatch` caps the applied batch per group (`--batch-limit`, 1–20, default 3) to candidates that already have a non-major `safeTarget`; every other safe candidate is listed as deferred instead of being silently available. Out-of-range limits throw before the plan is built.
- Deterministic coverage added in `scripts/dependency-update-plan.test.mjs`: store/usage grounding for the real `pino` entry, the workspace→lane mapping including the `.github` root dependent, shorthand-URL normalisation, and the batch cap including the major-never-selected case.

## Behavior

- Uses the pinned workspace `pnpm outdated --recursive --format json` command to read package and GitHub Actions candidates.
- Groups results as runtime, development, and Actions; records exact current/wanted/latest versions, dependents, compatibility class, safe GitHub releases/changelog URL when available, generation time, and source SHA.
- Reports both the wanted-range compatibility and latest-release compatibility separately, then marks one exact safe patch/minor target: prefer a wanted-range update; when wanted equals installed, allow only a stable latest patch/minor. Major, prerelease, and unknown targets remain report-only.
- The Monday scheduled/manual workflow checks out `dev`, has only `contents: read`, and uploads a seven-day JSON report. It creates no branch, pull request, issue, manifest edit, or lockfile update.
- Local report creation uses exclusive file creation so an existing report is never overwritten.
