Sudah tersedia di kode:

- [x] Satu slot akun WhatsApp per perusahaan dan device ID stabil.
- [x] Endpoint terautentikasi untuk status akun, connect/QR, disconnect, percakapan, pesan, dan media.

- [ ] Pairing QR GoWA, persistensi sesi setelah restart, kirim/terima pesan nyata.

API menerima receipt GoWA `message.ack` melalui webhook bertanda tangan HMAC dan hanya menaikkan status outbound (`sent → delivered → read`). Event `message` juga masuk ke cache percakapan/pesan secara idempotent; unread hanya bertambah untuk pesan inbound baru. Echo outbound yang tiba sebelum HTTP send ack direkonsiliasi ke row `sending` bila hanya ada satu kandidat cocok, mencegah konflik external ID dan pesan ganda. Device/company dipetakan lewat `session_id` dan account, sementara callback memvalidasi HMAC atas body mentah. Connect mendaftarkan event `message,message.ack` bila `WHATSAPP_WEBHOOK_URL` dan `WHATSAPP_WEBHOOK_SECRET` dikonfigurasi. Route tests menolak signature hilang/tidak valid, secret yang belum dikonfigurasi, dan body di atas 256 KiB (401/413); seluruh route suite lulus pada PostgreSQL disposable (57 passed, 1 skipped). Tes juga membuktikan device mismatch, receipt monotonik, pesan privat/grup/media, outbound echo idempotent, dan tenant terisolasi. Tetap terbuka sampai callback terpasang pada device GoWA nyata serta receipt delivered/read teramati.

## P1 — inbox dan sinkronisasi

- [x] **P1-01** Pagination daftar percakapan. API menerima `limit` 1–100 dan `offset` hingga 10.000, meneruskan halaman ke GoWA dan mengurutkan cache berdasarkan waktu pesan lalu ID. Board memuat 50 percakapan pertama dan menyediakan aksi Load more; tes API memastikan halaman pertama/kedua terurut benar dan provider menerima offset.
- [x] **P1-02** Pagination pesan lama. API menerima `limit` 1–100 dan `offset` 0–5000, meneruskan halaman ke GoWA, dan mengambil halaman cache berdasarkan urutan waktu plus ID; tes memeriksa query pagination provider serta isi halaman kedua.
- [x] **P1-03** Sinkronisasi incremental berdasarkan timestamp. Polling offset 0 mengirim `start_time` dari timestamp pesan cached terbaru dikurangi overlap 10 menit; GoWA menerima filter ISO-8601 `start_time` dan pagination `offset`. Tes mengonfirmasi nilai waktu overlap dan pagination. Sumber kontrak: [GoWA Chat API](https://github.com/aldinokemal/sdk-php-whatsapp-web-multidevice/blob/main/docs/Api/ChatApi.md).
- [x] **P1-04** Pencarian percakapan berdasarkan nama, nomor, dan isi pesan cached. API tetap menyinkronkan halaman percakapan normal dan, saat pencarian aktif, juga meminta GoWA `/chats?search=` (nama chat), lalu menggabungkan hasil dengan data company scope sebelum filter nama/JID/pesan cache dan pagination. Board mendebounce 250 ms. Pesan yang belum pernah disinkronkan tidak dapat dicari berdasarkan isi. Test route mencakup pencarian isi, nomor, pengiriman parameter GoWA, dan isolasi perusahaan. Parameter `search` didokumentasikan di [GoWA OpenAPI](https://github.com/aldinokemal/go-whatsapp-web-multidevice/blob/main/docs/openapi.yaml); kontrak khusus pada device hosted belum diuji.
- [x] **P1-05** Filter Semua, Belum dibaca, Pribadi, dan Grup. Board menyediakan empat filter; parameter `unread=true` difilter oleh API dalam company scope dan cache Board tetap memeriksa hitungan yang dikembalikan API. Route tests mencakup unread per user dan filter; E2E Chromium memverifikasi unread/private/group termasuk percakapan pribadi yang sudah dibaca.
- [ ] **P1-06** Unread count masih parsial. API menyimpan cursor baca per company, conversation, dan user; event webhook inbound baru menaikkan cache unread secara idempotent, sedangkan polling fallback menyinkronkan hingga 100 pesan terakhir ketika timestamp provider berubah. Contract test kode memakai endpoint GoWA `/chats`, tetapi OpenAPI pinned v9.6.0 tidak mendefinisikan endpoint tersebut maupun field `unread_count`, jadi belum ada kontrak publik yang dapat dijadikan sumber unread historis yang authoritative ([GoWA OpenAPI v9.6.0](https://github.com/aldinokemal/go-whatsapp-web-multidevice/blob/v9.6.0/docs/openapi.yaml)). Data lama sebelum webhook aktif atau saat callback tidak tersedia dapat kurang; jangan mengklaim hitungan lengkap. Tetap terbuka sampai kontrak host terverifikasi dan tersedia rekonsiliasi historis yang bounded serta diuji.
- [x] **P1-07** Aksi eksplisit menandai pesan inbound terbaru yang sudah tersimpan sebagai dibaca. API company-scoped mengirim GoWA `POST /message/{message_id}/read` dengan JID chat; setelah provider mengonfirmasi, API mencatat cursor baca terpisah untuk pengguna dan menulis audit log. Kegagalan provider tidak mengubah cursor. Tes route memverifikasi receipt, cursor, isolasi pengguna/perusahaan, dan unread count; belum diuji pada device hosted. Didukung kontrak [GoWA OpenAPI](https://github.com/aldinokemal/go-whatsapp-web-multidevice/blob/main/docs/openapi.yaml).
- [x] **P1-08** Perbarui preview pesan terakhir sebelum percakapan dibuka. Route test memastikan preview muncul sebelum chat dibuka dan request tidak diulang pada poll berikutnya. Daftar chat GoWA tidak mencantumkan isi pesan di schema; endpoint menyediakan `ChatMessage` beserta timestamp dan isi ([schema GoWA](https://github.com/aldinokemal/go-whatsapp-web-multidevice/blob/main/docs/openapi.yaml#L5711-L5845)).

- [x] **P2-03** Pengiriman lampiran Board → API kini memakai multipart; API memvalidasi dan hash file sambil mengalirkannya langsung ke attachment storage, tanpa Base64 atau buffer file penuh pada jalur upload. Tes multipart tepat di batas 10 MiB, penolakan lebih besar, file kosong, MIME palsu, storage gagal, idempotent retry, dan payload Base64 lama lulus pada SQLite/PostgreSQL (44 lulus, 1 acceptance S3 dilewati). E2E Chromium PostgreSQL memverifikasi QR, multipart boundary, caption, filename, byte file, dan draft saat API gagal (1/1 lulus).

- [ ] **P2-05** Upload langsung ke storage memakai URL singkat bertanda tangan dan izin perusahaan. API memeriksa ukuran dan MIME hasil HEAD, membaca isi dengan batas stream, memverifikasi signature file, menjalankan malware scan sebelum enqueue, menyalin byte terverifikasi ke key final yang immutable, dan mengonsumsi tiket sekali dalam transaksi. Tiket kedaluwarsa dibersihkan oleh attachment reconciler. Board mengunggah langsung tanpa kredensial API dan tetap mendukung multipart saat storage tidak mendukung presigned POST. Unit API mencakup scope, tiket sekali pakai, replay, expired ticket, MIME dan malware; E2E Chromium membuktikan multipart/direct POST, storage 503 dengan draft tetap utuh, dan retry sukses. Yang masih terbuka: verifikasi CORS serta alur upload nyata pada Garage deployment dan operasi produksi; karena itu checklist belum ditutup.
